# Состояние проекта

Дата текущей работы: 2026-10-23 (Asia/Yekaterinburg).

## Уточнение по `spawn EPERM` (23.10.2026)

Независимый запуск в обычном PowerShell Windows подтвердил, что проблема не
относится к исходному коду frontend: `Node.js child_process.spawnSync()` запускает
`frontend/node_modules/.pnpm/esbuild@0.28.2/node_modules/esbuild/esbuild.exe`
успешно (`status: 0`, версия `0.28.2`), а `node
node_modules/vite/bin/vite.js build` проходит с обработкой 1848 модулей.
Production-сборка того же исходного дерева также прошла внутри Docker при обновлении
тестового стенда `e29-stage3-acceptance`.

В Codex sandbox дочерний запуск блокируется на границе `ChildProcess.spawn` с
`EPERM` до выполнения тестов или Vite build. В этой среде файл существует, имеет
расширение `.exe`, прямой запуск и Docker build работают, но политика sandbox
ограничивает создание дочернего процесса из локального Node/Vite shell. Это
средовая блокировка Codex, а не ошибка проекта, ассоциации Windows или установка
esbuild. Node.js, pnpm, esbuild и `node_modules` не переустанавливались.

Рекомендуемый устойчивый запуск frontend-проверок: обычный пользовательский
PowerShell Windows из `frontend` (`node node_modules/vitest/vitest.mjs run`,
`node node_modules/vite/bin/vite.js build`, `node node_modules/prettier/bin/prettier.cjs
--check ...`) либо Docker build для production-сборки. Постоянная пересборка
контейнеров для каждого запуска не нужна; Docker использован только как безопасное
подтверждение и для обновления тестового frontend на 8082. В Codex остаются
непроверенными только локальный Vitest-прогон и локальный Vite build; их результаты
нельзя маркировать как ошибки проекта.

## Реальные падения Vitest и их исправления (23.10.2026)

Независимый запуск Vitest в обычном PowerShell дал **37 passed / 43 tests / 6
failed**. Причины установлены по исходному коду и фикстурам:

- четыре падения `item-workflow.test.tsx` были вызваны тестовой фикстурой:
  проверка `endsWith('/categories?')` не совпадала с фактическим URL
  `categories?limit=100...`, поэтому список категорий оставался пустым и select
  был disabled. Фикстура исправлена на проверку `includes('/categories?')`;
  ожидание ошибки кода категории обновлено под актуальную автогенерацию кода.
- падение `warehouse.test.tsx` выявило дефект `StockForm`: при выбранном Employee
  `recipient_building` и часть реквизитов исключались из payload. Теперь здание,
  кабинет и подразделение передаются по актуальному контракту независимо от
  способа выбора получателя; ожидание сохранено как регрессионная проверка.
- падение `app.test.tsx` относилось к асинхронному пустому состоянию перемещений;
  проверка переведена на ожидание DOM после завершения загрузки, без ослабления
  текста или удаления assertion.

После исправлений в Codex проверены TypeScript, Prettier и Ruff. Полный Vitest
здесь не запускается из-за sandbox-ограничения `spawn EPERM`; финальная команда в
обычном PowerShell: `cd frontend; node node_modules/vitest/vitest.mjs run`.

Актуальное уточнение после запуска вне sandbox (23.10.2026): команда выполнена в
обычном Windows PowerShell и завершилась успешно — **6 файлов, 45/45 тестов**.
Production-сборка Vite также завершилась успешно после обработки **1849 модулей**.
Таким образом, `spawn EPERM` относится только к среде Codex и не является текущей
ошибкой проекта; старые упоминания о незапущенном локальном прогоне ниже сохранены
как исторический журнал диагностики.

### UX каталога склада (23.10.2026)

- Каталог использует единый источник данных и получил три режима отображения:
  карточки по умолчанию, компактный список и таблица. Переключатель доступен с
  клавиатуры, использует Lucide-иконки и сохраняет режим в
  `localStorage` (`warehouse.catalog.view`). Поиск, фильтры, сортировка, пагинация
  и экспорт не зависят от выбранного режима.
- Карточки показывают same-origin фото или нейтральную заглушку, название,
  производителя, категорию, артикул, остаток, предупреждение минимума и действие
  добавления. Длинные названия ограничены тремя строками, полный текст доступен
  через `title` и ссылку на существующую карточку позиции.
- Существующий черновик выдачи остаётся единственной корзиной. Кнопка
  `Корзина (N)` закреплена в шапке каталога, а после добавления появляется
  уведомление «Позиция добавлена в корзину» со ссылкой «Перейти в корзину» на
  `/issues`. Остатки и API проведения при простом добавлении не меняются.
- Тесты нового поведения добавлены в `frontend/src/test/catalog.test.tsx`.
  Полный Vitest прошёл **45/45 (6 файлов)** в обычном Windows-сеансе. Во время
  промежуточного прогона был найден и исправлен устаревший тестовый селектор
  режима; последующий targeted-каталог прошёл 8/8, финальный полный прогон —
  45/45. TypeScript, Prettier и `git diff --check` проходят. Production build
  Vite прошёл (1849 модулей); осталось вручную проверить desktop/mobile в
  браузере и визуально принять результат. БД, миграции, `.env`, volumes и Docker
