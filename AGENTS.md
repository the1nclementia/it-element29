# Правила проекта ИТ-элемент [29]

- Текущий объём работ — этап 1. Не расширять этап без запроса пользователя.
- Модульный монолит: API → application/service → SQLAlchemy → PostgreSQL.
- Python 3.12+, SQLAlchemy 2, Pydantic 2. PostgreSQL — единственная основная БД.
- Русский язык для документации и пользовательских сообщений; английский для идентификаторов кода.
- Не переносить старый Windows GUI и не изменять CartridgeDesk.
- Перед изменением поведения написать проверку, воспроизвести отказ, затем реализовать.
- Запускать pytest, Ruff и применимые интеграционные проверки. Не выдавать пропуски за успех.
- Миграции Alembic явные и неизменяемые после выпуска. Не применять create_all при старте сервера.
- API не выполняет миграции; отдельный процесс deploy выполняет их ровно один раз.
- Все будущие бизнес-endpoint требуют серверных permissions; публичны только health probes.
- SQL только с параметрами. Транзакция охватывает документ, строки, движение и аудит.
- UUID как ключи, timestamptz в UTC, архивирование без удаления истории.
- Остаток рассчитывается по inventory_movements; операции блокируют строку inventory_items FOR UPDATE.
- Текущее положение equipment — единственный источник текущего состояния; история не заменяет его.
- Не помещать пароли, токены, персональные данные, реальные базы, загруженные файлы в Git или логи.
- Никаких облачных API для корпоративных данных. Логотипы не перерисовывать.
- Перед завершением обновить PROGRESS.md, проверить diff и создать осмысленный локальный коммит.
